## Architecture

**Two page-shell patterns coexist:**

1. **The one-pager** — `src/pages/home.tsx` is the live site: a single page with anchor-linked sections (`#about`, `#exhibitions`, `#contact`), its own inline header/footer, styled entirely by `src/styles/components/home.scss` (everything scoped under `.home`). `src/pages/index.tsx` is just a client-side redirect to `/home/`. The navbar (`src/components/navBar.tsx`) only links to `/home/` and its anchors plus `/artwork/...`.
2. **The shared `layout.tsx` shell** — used by everything else: the artwork gallery/detail pages (`src/templates/artwork/collection.js`, `artworkDetailPage.js`, generated by `gatsby-node.js`), `src/pages/imprint.tsx`, and `src/pages/404.tsx`.

**Page generation (`gatsby-node.js`)**: `createPages` groups every artwork markdown node by *all* the categories it declares in frontmatter (a piece can belong to more than one category, e.g. a sketch also sold as a postcard — it's grouped under every one, not just the first), computes per-category and "all" counts (a unique file count, not a sum, so multi-category pieces aren't double-counted), then creates:
- one detail page per markdown file (`artworkDetailPage.js`), with prev/next slugs computed from sibling order within that node's *primary* (first-listed) category, in the same date-DESC order used for the gallery grids;
- one or more collection/gallery pages per category (`collection.js`), with pagination gated behind the `activatePagination` flag in `src/constants.js` (currently off, so each category is a single page showing everything regardless of count).

**Data sources**: artwork markdown files live under `src/assets/artwork/mdfiles/` (frontmatter includes `title`, `category` as string or string[], `date`, `sold`, `material`, `size`, `image`, `imagePreview`), sourced via `gatsby-source-filesystem` + `gatsby-transformer-remark`. 

**Constants**: `src/constants.js` is the single place for cross-cutting config.

**Styling**: SCSS via `gatsby-plugin-sass`. One file per page/section under `src/styles/components/` (e.g. `home.scss`, `collection.scss`, `artworkDetail.scss`), each scoped under a root class (e.g. everything in `home.scss` is nested under `.home`) so page styles don't bleed into each other. Shared tokens (colors, etc.) live in `src/styles/_variables.scss`. The navbar/header (`_navbar.scss`) is the one style file that's genuinely site-wide, since `navBar.tsx` is shared by every page regardless of which layout generation it belongs to.

**Responsive breakpoints**: `home.scss` uses a single `max-width: 640px` mobile query throughout. The navbar's hamburger-collapse breakpoint is `max-width: 992px` (tied to react-bootstrap's `Navbar expand="lg"` in `navBar.tsx` — changing one without the other will desync when the burger button actually appears); `_navbar.scss` also has its own narrower `max-width: 640px` block for phone-only tightening (header height, logo size) layered on top of the 992px tablet/mobile block.

**Note**: both `gatsby-browser.js` and `gatsby-browser.tsx` exist in the repo root. This is a pre-existing oddity, not intentional dual-config — check which one Gatsby is actually resolving before adding to either.
